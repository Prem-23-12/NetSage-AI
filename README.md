# NetSage AI  
### Evidence-Grounded Network Troubleshooting with Human-in-the-Loop AI

NetSage AI is an AI-assisted troubleshooting tool designed for Cisco-style networking labs and Packet Tracer environments. It combines deterministic Python rule checks with AI-generated diagnoses to help identify potential network configuration issues, explain likely root causes, and recommend corrective actions.

**Human oversight is a core design principle:** AI-generated diagnoses are not treated as final until a human reviewer accepts, edits, or rejects them.

The project also evaluates the reliability of AI diagnoses by checking evidence grounding, recording reviewer corrections, and visualizing results through an interactive Streamlit dashboard.
  
## Key Features

- **Deterministic rule checking:** Detects supported configuration issues using predefined Python rules.
- **AI-assisted diagnosis:** Uses the Groq API to generate structured diagnoses and recommended fixes.
- **Evidence-grounding checks:** Flags AI claims that may not be supported by the available network evidence.
- **Human-in-the-loop review:** Records accepted, edited, and rejected diagnoses along with categorized correction reasons.
- **Reliability analytics:** Visualizes diagnosis outcomes, grounding flags, human agreement, and correction patterns.
- **Responsible AI documentation:** Records important corrections, limitations, and observations from the evaluation process.

## Supported Troubleshooting Categories

NetSage AI includes **32 troubleshooting cases across eight categories**:

| Category | Example investigation area |
|---|---|
| VLAN | VLAN configuration and assignment |
| Gateway | Default gateway mismatches |
| DHCP | Address allocation and configuration |
| DNS | Name resolution configuration |
| Routing | Missing or incorrect routes |
| ACL | Access control and filtering rules |
| NAT | Network address translation |
| Wireless | Wireless connectivity issues |

Detection coverage depends on the rules, evidence, and cases implemented in the current version. Not every possible fault in these categories is automatically detected.

## Project Architecture

The project follows a staged troubleshooting and review workflow:

1. **Network case input** — Load symptoms and available show-command evidence.
2. **Deterministic analysis** — Run Python rules against supported configuration indicators.
3. **AI diagnosis** — Generate a structured diagnosis using the Groq API.
4. **Grounding evaluation** — Check cited evidence and flag potentially unsupported claims.
5. **Human review** — Accept, edit, or reject the diagnosis and document corrections.
6. **Reliability dashboard** — Analyze review outcomes and diagnostic performance using Streamlit.

```text
Troubleshooting Cases
        |
        v
Python Rule Checker
        |
        v
AI Diagnosis (Groq API)
        |
        v
Evidence-Grounding Evaluation
        |
        v
Human Review and Corrections
        |
        v
Streamlit Analytics Dashboard
```

## Installation and Setup

### Prerequisites

- Python 3.10 or a compatible version supported by your dependencies
- pip
- Git, if cloning the repository
- A Groq API key only if you intend to run live AI diagnoses

### 1. Clone the repository

```bash
git clone https://github.com/YOUR_USERNAME/NetSage-AI.git
cd NetSage-AI
```

Replace `YOUR_USERNAME` with your GitHub username and use your actual repository URL.

### 2. Create a virtual environment (recommended)

**Windows:**

```bash
python -m venv .venv
.venv\Scripts\activate
```

**Linux/macOS:**

```bash
python3 -m venv .venv
source .venv/bin/activate
```

### 3. Install dependencies

```bash
python -m pip install --upgrade pip
pip install -r requirements.txt
```

Ensure `requirements.txt` includes every package imported by the current application and scripts. If `groq_runner.py` uses `requests`, include `requests` in that file rather than relying on a separate system-wide installation.

## Running the Project

Run the stages in the following order when generating a fresh evaluation dataset.

### Step 1 — Run deterministic checks

```bash
python rule_checker.py
```

This runs the supported Python rules against the troubleshooting cases and generates the rule findings file.

### Step 2 — Generate AI diagnoses

Set your Groq API key using an environment variable.

**Windows PowerShell:**

```powershell
$env:GROQ_API_KEY="YOUR_GROQ_API_KEY"
python groq_runner.py
```

**Linux/macOS:**

```bash
export GROQ_API_KEY="YOUR_GROQ_API_KEY"
python3 groq_runner.py
```

For an offline dry run, if supported by the current script:

```bash
python groq_runner.py --mock
```

Use a valid API key for live inference. Never commit your API key to GitHub or place it in source code.

### Step 3 — Inspect flagged diagnoses

```bash
python inspect_flagged.py
```

Review the output and investigate claims that may not be supported by the available evidence. A grounding flag is a signal for review, not by itself proof that a diagnosis is incorrect.

### Step 4 — Perform human review

Review the diagnoses and maintain `data/review_log.csv` using the fields expected by the application. Depending on the implementation, these may include:

- Case identifier
- Review decision: `Accepted`, `Edited`, or `Rejected`
- `correction_reason`
- `corrected_root_cause`
- `reviewer_notes`

Document the actual reviewer decision for each reviewed case. Do not label a diagnosis as accepted or corrected unless that review has taken place.

### Step 5 — Prepare dashboard data

Generate or update `data/dashboard_data.csv` using the project's implemented data-preparation workflow. Ensure that it corresponds to the same versions of `cases.csv`, `rule_findings.csv`, `ai_diagnoses.csv`, and `review_log.csv`.

If your project does not yet have an automated data-preparation script, update the joined dataset using a reproducible manual or Python workflow.

### Step 6 — Launch the dashboard

```bash
streamlit run app.py
```

Open the local URL displayed in your terminal to explore the dashboard.

## Dashboard and Evaluation

The dashboard is designed to help reviewers investigate the relationship between AI diagnoses, supporting evidence, and human decisions.

Depending on the metrics implemented in the current version, it can present:

- Troubleshooting case distribution by category
- Deterministic rule findings
- AI diagnosis and grounding-flag summaries
- Human review decisions and agreement
- Correction reasons and recurring error patterns
- Confidence-versus-correctness analysis, where suitable reviewed data is available

**Important:** These metrics describe the evaluated dataset and review process. They should not be interpreted as proof of general reliability across all networks or configurations.

## Responsible AI and Human Oversight

NetSage AI is designed to make AI-assisted troubleshooting more inspectable and accountable.

Its responsible AI workflow emphasizes:

- **Evidence-based reasoning:** Diagnoses should be supported by the supplied network evidence.
- **Transparency:** Reviewers can inspect rule findings and AI-generated explanations.
- **Human accountability:** A reviewer makes the final decision.
- **Error documentation:** Corrections and reasons are recorded for further analysis.
- **Limitations awareness:** Automated grounding checks can produce false positives or miss unsupported claims.
- **Reproducibility:** Evaluation results should be tied to the exact input, diagnosis, and review datasets used.

See `responsible_ai_log.md` for the documented case reviews and evaluation observations.

## Deployment on Streamlit Community Cloud

1. Push the complete project to a GitHub repository.
2. Open [Streamlit Community Cloud](https://share.streamlit.io/).
3. Sign in using GitHub.
4. Select **Create app** or **New app**.
5. Choose the repository, branch, and `app.py` as the main file.
6. Deploy the application.

Before deployment:

- Confirm that every CSV loaded by `app.py` exists in the repository.
- Include required assets and all necessary dependencies.
- Ensure the dashboard can start without a Groq API key if it only reads previously generated CSV files.
- If live AI inference is required in the deployed app, configure `GROQ_API_KEY` using Streamlit secrets.
- Never commit `.env` files, API keys, or `.streamlit/secrets.toml`.
- Verify that the deployed dashboard displays the expected case counts and evaluation metrics.

## Demo Walkthrough

7. Conclude with key observations, limitations, and future improvements.
